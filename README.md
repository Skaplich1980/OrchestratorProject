
# 🤖 Python Project Orchestrator

Мульти-агентный CLI-оркестратор для автоматизации задач в Python-проектах. Система самостоятельно анализирует цель, разбивает её на атомарные шаги, выполняет правки кода и проверяет результат.

## ⚙️ Как это работает (Архитектура)

1. **Планировщик (Planner):** Динамически запрашивает у OpenRouter список бесплатных моделей (`:free`) с большим контекстом. Если они недоступны, использует резервные модели из `.env` (например, DeepSeek). Генерирует строгий JSON-план шагов.
2. **Исполнитель (Executor):** Вызывает **Agnes Code CLI** для выполнения каждого шага. Перед правками автоматически создаёт бэкапы целевых файлов и внедряет `.agneshints` для точного контекста.
3. **Ревьюер (Reviewer):** Анализирует `stdout`/`stderr` и код возврата от Agnes. Если шаг выполнен некорректно, оркестратор останавливается с явной причиной.

## 🚀 Быстрый старт

### 1. Требования
- Python 3.12+
- Установленный и добавленный в `PATH` исполняемый файл **Agnes Code** (`agnes`)
- Виртуальное окружение

### 2. Установка
```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Настройка `.env`
Скопируй `.env.example` в `.env` и заполни своими данными:
```env
# API Ключи
OPENROUTER_API_KEY=sk-or-v1-ТВОЙ_КЛЮЧ
DEEPSEEK_API_KEY=sk-ТВОЙ_КЛЮЧ (опционально, как fallback)

# Модели (через запятую, без пробелов). Используются, если free-модели недоступны.
FALLBACK_PLANNER_MODELS=qwen/qwen-2.5-72b-instruct,deepseek/deepseek-chat
FALLBACK_REVIEWER_MODELS=qwen/qwen-2.5-72b-instruct,deepseek/deepseek-chat

# Agnes Code
AGNES_CLI_PATH=agnes
AGNES_TIMEOUT=300

# Целевой проект
DEFAULT_PROJECT_PATH=D:\Project\garden_helper

# Лимиты и задержки
LOG_LEVEL=DEBUG
MAX_STEPS=10
MAX_RETRIES=2
RETRY_DELAY=5.0
RETRY_BACKOFF=2.0
DELAY_BETWEEN_CALLS=5.0

# Бэкапы
ENABLE_BACKUPS=true
BACKUP_DIR=./backups
```

### 4. Создание цели
Создай файл `goal.txt` в целевом проекте (например, `D:\Project\garden_helper\goal.txt`).
> ⚠️ **ВАЖНО:** Файл **обязательно** должен быть сохранён в кодировке **UTF-8** (в Блокноте: Файл → Сохранить как → Кодировка: UTF-8).

Пример содержимого `goal.txt`:
```text
Создай файл config.py с классом Settings на базе pydantic. Добавь поле database_url со значением по умолчанию "sqlite:///garden.db".
```

### 5. Запуск
```bash
python orchestrator.py --goal "D:\Project\garden_helper\goal.txt"
```
*(Флаг `--project` можно опустить, если `DEFAULT_PROJECT_PATH` корректно указан в `.env`)*

## 📂 Структура логов и отладка

Оркестратор создаёт новую папку для каждого запуска: `logs/run_YYYY-MM-DD_HH-MM-SS/`.

### Файлы в папке запуска:
| Файл | Описание |
| :--- | :--- |
| `run.log` | **Общий лог.** Хронология всех событий от всех агентов в одном месте. |
| `planner.log` | Детальный лог планировщика (включая полные промты и сырые ответы моделей при `LOG_LEVEL=DEBUG`). |
| `executor.log` | Лог вызовов Agnes CLI (команды, stdout, stderr, код возврата). |
| `reviewer.log` | Лог проверки результатов (промт с данными исполнителя и вердикт). |
| `structured_trace.jsonl` | **Машиночитаемый лог.** Каждая строка — JSON-объект события. Идеально для парсинга скриптами или анализа в Pandas. |
| `backups/` | Папка с копиями файлов (`step_001/`, `step_002/`), изменённых Agnes перед каждым шагом. |

### Формат строки лога:
```text
[2026-10-26 17:22:42.673] [planner/qwen-2.5-72b-instruct:free] [DEBUG] --- СЫРОЙ ОТВЕТ МОДЕЛИ ---
```
* `[TIMESTAMP.ms]` — точное время.
* `[ROLE/MODEL]` — кто и какая модель генерирует запись.
* `[LEVEL]` — `DEBUG` (промты/ответы), `INFO` (статус), `WARNING` (retry), `ERROR` (сбой).

## 🛠 Решение частых проблем

| Симптом | Причина | Решение |
| :--- | :--- | :--- |
| `UnicodeDecodeError: 'utf-8' codec can't decode...` | Файл `goal.txt` сохранён в ANSI (Windows-1251). | Открой в Блокноте → Сохранить как → Выбери кодировку **UTF-8**. |
| `Agnes binary not found` | Неверный путь к исполняемому файлу Agnes. | Укажи полный путь в `.env`: `AGNES_CLI_PATH=C:\Program Files\Agnes\agnes.exe` |
| `403 Forbidden` в логе планировщика | OpenRouter ограничил конкретную `:free` модель для прямых API-вызовов. | **Нормальное поведение.** Оркестратор автоматически пропустит её и переключится на следующую модель из списка (fallback). |
| Ревьюер постоянно возвращает `success=false` | Задача слишком большая для одного шага, или Agnes не справляется. | Уменьши `MAX_STEPS` в `.env` и разбей задачу в `goal.txt` на более атомарные подзадачи. |

## 🔒 Безопасность и Guardrails

1. **Бэкапы:** Перед каждым шагом файлы из `target_files` копируются в `logs/run_.../backups/step_NNN/`.
2. **Изоляция:** Agnes запускается с флагом `--no-session`, чтобы не накапливать контекст между шагами.
3. **Контекст:** Оркестратор автоматически создаёт `.agneshints` в корне целевого проекта, если его нет, чтобы Agnes понимал правила проекта.
4. **Per-turn инструкции:** В окружение Agnes инжектируется `AGNES_MOIM_MESSAGE_TEXT` с жёсткими правилами (не удалять файлы, делать минимальные правки), которые невозможно «забыть» при переполнении контекста.
