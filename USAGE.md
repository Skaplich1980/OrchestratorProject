1. Подготовка цели (goal.txt)
Создайте файл goal.txt в целевом проекте, например:

text
D:\Project\garden_helper\goal.txt
⚠️ ВАЖНО: Файл обязательно должен быть сохранён в кодировке UTF-8.
В Блокноте: Файл → Сохранить как → Кодировка: UTF-8.

Пример содержимого goal.txt
text
Создай файл config.py с классом Settings на базе pydantic.
Добавь поле database_url со значением по умолчанию "sqlite:///garden.db".
💡 Совет: чем атомарнее подзадачи в goal.txt, тем выше шанс, что ревьюер вернёт success=true с первого шага. Слишком большая задача → уменьшите MAX_STEPS в .env и разбейте цель на несколько мелких.

2. Запуск
bash
python orchestrator.py --goal "D:\Project\garden_helper\goal.txt"
Флаги
Флаг	Обязателен	Описание
--goal	✅ Да	Путь к файлу goal.txt с описанием цели.
--project	❌ Нет	Путь к целевому проекту. Можно опустить, если DEFAULT_PROJECT_PATH корректно указан в .env.
3. Где смотреть результат и логи
Сразу после запуска в корне оркестратора появляется папка:

text
logs/run_YYYY-MM-DD_HH-MM-SS/
Каждый запуск создаёт новую папку — старые логи не перезаписываются.

📂 Структура логов
Файл / папка	Описание
run.log	Общий лог. Хронология всех событий от всех агентов в одном месте.
planner.log	Детальный лог планировщика (включая полные промты и сырые ответы моделей при LOG_LEVEL=DEBUG).
executor.log	Лог вызовов Agnes CLI (команды, stdout, stderr, код возврата).
reviewer.log	Лог проверки результатов (промт с данными исполнителя и вердикт).
structured_trace.jsonl	Машиночитаемый лог. Каждая строка — JSON-объект события. Идеально для парсинга скриптами.
backups/	Папка с копиями файлов (step_001/, step_002/), изменённых Agnes перед каждым шагом.
models_cache.json	Кэш доступных моделей (обновляется автоматически раз в 7 дней).
🔍 Быстрая проверка результата
Откройте run.log. Ищите строки с [INFO] и [ERROR]. Там будет видно:

"Начало планирования"

"Шаг 1 выполнен"

"Ревью: success=true"

Если что-то пошло не так:

Откройте run.log с LOG_LEVEL=DEBUG (в .env) — увидите полные промты и ответы моделей.

Или посмотрите planner.log, чтобы понять, какой именно промт ушёл в модель и что она ответила.

Восстановление файлов: все изменённые файлы перед правкой лежат в logs/.../backups/step_001/ — их всегда можно вернуть.

Кэш моделей: файл models_cache.json в корне оркестратора покажет, какие модели и роутеры были найдены и в каком порядке они будут использоваться.

4. Решение частых проблем
Симптом	Причина	Решение
UnicodeDecodeError: 'utf-8' codec can't decode...	Файл goal.txt сохранён в ANSI (Windows-1251).	Откройте в Блокноте → Сохранить как → выберите кодировку UTF-8.
Agnes binary not found	Неверный путь к исполняемому файлу Agnes.	Укажите полный абсолютный путь в .env: AGNES_CLI_PATH=C:\Path\To\agnes.exe
Rate limit exceeded в логе планировщика	Превышен лимит бесплатных запросов текущего роутера.	Нормальное поведение. Оркестратор автоматически и мгновенно переключится на следующую модель или роутер из очереди.
Ревьюер постоянно возвращает success=false	Задача слишком большая для одного шага.	Уменьшите MAX_STEPS в .env и разбейте задачу в goal.txt на более атомарные подзадачи.
5. Безопасность и Guardrails
Механизм	Что делает
Бэкапы	Перед каждым шагом файлы из target_files копируются в logs/run_.../backups/step_NNN/.
Изоляция	Agnes запускается с флагом --no-session, чтобы не накапливать контекст между шагами.
Контекст проекта	Оркестратор автоматически создаёт .agneshints в корне целевого проекта, если его нет, чтобы Agnes понимал правила проекта.
Per-turn инструкции	В окружение Agnes инжектируется AGNES_MOIM_MESSAGE_TEXT с жёсткими правилами (не удалять файлы, делать минимальные правки), которые невозможно «забыть».
